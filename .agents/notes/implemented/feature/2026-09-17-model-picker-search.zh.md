# Agent Note: 模型选择器搜索

Status: implemented

[English](2026-09-17-model-picker-search.md) | 中文

## 问题

模型选择器会按提供方分组渲染每一个已配置模型。拥有多个提供方或大型目录的用户即使已经知道模型或提供方标识符，也必须扫描完整列表。

## 决策

模型面板在提供方分组上方包含一个本地化搜索输入框。Client 会去除查询两端的空白并把字母转换为小写，然后对每个提供方名称、提供方 ID、模型名称和模型 ID 做子字符串匹配。匹配结果保留原有的提供方分组和顺序，没有匹配模型的分组会消失。

规范化后的空查询显示完整目录。非空查询没有匹配项时显示独立的搜索空状态，不会改变目录本身的无模型状态。每次打开选择器都会清除查询，因此过滤条件不会延续到之后的访问。选择过滤后的结果仍使用现有会话选择路径，不改变目录加载或提供方探测。

## 考虑过的替代方案

**只搜索模型名称。** 显示名称适合浏览，但不是稳定标识符，而且用户通常会从配置中复制提供方与模型 ID。搜索全部四种可见或已配置标识符，使已知值查找可靠，无需增加另一种搜索模式。

**把匹配模型展平成一个列表。** 扁平结果可以减少标题，但提供方身份能够区分重名模型，并说明选择所使用的已配置路由。保留分组也让过滤前后的导航保持一致。

**保留上一次查询。** 立即重新打开时，保留查询可以省去再次输入，但它可能让下一次选择时的模型看起来像是缺失了。打开时清除查询，使每次访问默认显示完整目录。

## 后果

过滤完全在已加载目录的本地完成，不会发出提供方请求。选择器保留提供方上下文和选择行为，同时减少浏览大型目录所需的扫描。搜索输入为模型面板增加一个本地化控件和一个空结果状态。

## 测试

ModelSelect 组件测试覆盖带两端空白且不区分大小写的模型 ID 匹配、提供方名称与提供方 ID 匹配、空查询、无匹配结果、从过滤结果中选择，以及重新打开后的查询重置。
